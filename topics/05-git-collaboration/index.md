# Version control and collaboration with Git

Until now, `ledger` lived only in a folder on your laptop, and its only history was your memory. In this session it gets a real history and a home on GitHub. You learn how **Git** records a project as a series of snapshots, how a local repository and GitHub exchange work, and how a team works in parallel with **branches**, combines that work with **merges**, deals with **conflicts** and reviews changes through **pull requests**. Then you do all of it, by hand, in the repository where you will build your application for the rest of the course.

## The thread of the session

1. **[Version control with Git](git.md).** Commits, the working tree and the staging area, `.gitignore`, remotes, branches, merges, conflicts and pull requests.
2. **[Lab 5: your app's repository](lab.md).** You create your repository on GitHub, add the ledger, and go through the whole workflow: commit, push, pull, branch, conflict and pull request. **Submit the URL of your repository on Blackboard by Friday 13 November, 23:59.** This lab is done without AI.

## Objectives

By the end of the session you should be able to:

- [ ] Explain what a commit is, and move changes from the working tree to the staging area and into a commit.
- [ ] Decide which files of a project go into the repository, and keep the rest out with `.gitignore`.
- [ ] Create a repository on GitHub, clone it, and exchange commits with it using `push` and `pull`.
- [ ] Create a branch, commit on it and publish it.
- [ ] Explain when a merge is a fast-forward and when it needs a merge commit.
- [ ] Resolve a merge conflict by editing the file, and finish the merge.
- [ ] Open a pull request with a useful description and merge it with a merge commit.
